## 2. Where Real Captures Were Chosen Over AI

1. **Component UI & Validation States**:
   - **Decision**: Used real browser screenshots of `SettingsForm` rather than AI-generated UI mockups.
   - **Rationale**: AI-generated UI mockups create synthetic, unrealistic form elements with fake typography. Showing actual DOM elements with active `aria-invalid="true"` attributes proves that the code functions in a real browser.

2. **Vitest Unit Test Execution**:
   - **Decision**: Used actual terminal execution logs (`vitest run` output: *8 passed in 280ms*) instead of generated illustrations.
   - **Rationale**: Senior Tech Leads look for verifiable proof. Real terminal output displaying Vitest execution metrics substantiates the core claim (*test-driven React code*) beyond doubt.

3. **Developer Headshot**:
   - **Decision**: Used a real professional human photo instead of an AI-generated avatar.
   - **Rationale**: Synthetic AI avatars create an immediate sense of uncanny disconnect and suspicion. Human hiring leads hire real engineers, requiring authentic presentation.

## 3. Ruthless Rejection Log (Discernment & Judgment)

To maintain the Voice Card (*direct, technical, plainspoken, pragmatic, zero buzzwords, evidence-first*), the following AI-generated options were explicitly rejected:

### ❌ Rejected Image 1: 3D Floating React Logo with Particle Effects
- **Description**: An AI-generated 3D glassmorphic React logo floating above glowing violet particle clouds.
- **Rejection Reason**: *Rejected because 3D floating tech graphics look like generic marketing agency fluff. They add zero evidence of technical competence, distract from the code, violate our 7-word voice card, and look like a template.*

### ❌ Rejected Image 2: AI-Generated IDE Code Screen with Rainbow Syntax
- **Description**: An AI-generated screenshot depicting a futuristic dark IDE displaying colorful lines of code.
- **Rejection Reason**: *Rejected because generated code screenshots render garbled TypeScript syntax, non-existent methods, and fake HTML tags upon close inspection. A Senior Tech Lead inspecting a case study will immediately spot fake code, destroying credibility. Real VS Code and Vitest terminal logs were retained instead.*

## 4. Style & Consistency Rules for AI Connective Assets

For secondary connective assets (background textures and subtle card accents), the following strict prompt rules were enforced:

- **Palette Alignment**: Background `#0f172a`, Grid lines `#6366f1` at 5% opacity.
- **Style Constraint**: Minimalist, flat architectural geometry, zero 3D glows, zero realistic lighting, low visual noise.
- **Consistency Rule**: All connective graphics must serve as a low-contrast backdrop so that real code captures remain the highest-contrast, loudest elements on the screen.
